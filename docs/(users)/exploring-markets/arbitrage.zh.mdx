套利在 <SiteName />
和 Polymarket 上购买相同数量的互补结果份额。如果总成本（包括预估费用）低于每对 $1.00，
持有到解析后返回的收益可能高于成本。

<Callout type="info" title="核心条件">
  **结果A价格 + 结果B价格 + 预估费用必须低于每对 $1.00。**
</Callout>

结果标签不需要是"是"和"否"。它们可以是"上涨/下跌"或两个 opposing 团队，
只要结果是互补的且恰好有一个在解析时支付 $1.00。

**套利（Arbitrage）**选项卡仅在集成启用且所选市场有兼容的 Polymarket 镜像时显示。此功能目前处于测试阶段。

## 示例

假设订单簿可以填充 100 对匹配：

| 腿                     |  价格 | 份额 |        成本 |
| ---------------------- | ----: | ---: | ----------: |
| <SiteName /> 上的结果A | $0.42 |  100 |      $42.00 |
| Polymarket 上的结果B   | $0.53 |  100 |      $53.00 |
| 预估费用               |       |      |       $1.00 |
| **总成本**             |       |      |  **$96.00** |
| **解析收益**           |       |      | **$100.00** |
| **预估利润**           |       |      |   **$4.00** |

计算方式为：

```text
匹配份额 × ($1.00 − 综合价格 − 每对费用)
100 × ($1.00 − $0.95 − $0.01) = $4.00
```

无论哪个结果获胜，100 份获胜份额兑换 $100，另 100 份份额
兑换 $0。

<Callout type="warning">
  此示例仅供参考。使用实时报价：它考虑了订单簿深度、费用、余额、最小数量和 两条腿都能填充的数量。
</Callout>

## 提交套利订单

<Steps>
  <Step>
    ### 打开套利

    在订单面板中选择**套利（Arbitrage）**。

  </Step>
  <Step>
    ### 审查两条腿

    确认结果、平台、可执行价格、预估费用和每个平台的预期回报。

  </Step>
  <Step>
    ### 选择匹配数量

    输入数量或使用最小、中或最大。最大数量受有利可图的流动性和
    两个平台上可用的余额限制。

  </Step>
  <Step>
    ### 签名两个订单

    每条腿都需要签名。一个订单发送到 <SiteName /> CLOB，
    互补订单发送到 Polymarket。

  </Step>
  <Step>
    ### 验证结果

    检查两个报告的状态和你提交另一笔订单前的仓位。

  </Step>
</Steps>

## 执行风险

两个订单不是一个原子交易。虽然每条腿使用成交或取消
执行，但一条腿可以成交而另一条失败。这会创建暂时的方向性
敞口。

签名前确认：

- 两个平台都有足够的余额；
- 报价数量相等；
- 市场使用兼容的解析标准；
- 费用后预期利润仍为正；
- 你可以监控和纠正部分结果。

<Callout type="warning" title="解析标准必须匹配">
  相似的市场标题不保证相同的结果。在使用跨平台套利前，比较两个平台上的规则、日期、来源和边缘情况。
</Callout>

## 常见问题

### 为什么最大值低于我的余额？

最大值受两个余额的较小值、两条腿共享的有利可图的流动性、最小订单规则和交易所数量舍入的限制。

### 我可以在解析前退出吗？

可以，但显示的套利回报假设相等相反的头寸持有到解析。提前出售会创建在当前价格的新交易并改变结果。

### 如果只有一条腿成交了该怎么办？

在采取行动前审查已完成的腿和当前订单簿。根据价格和
流动性，你可以重试缺失的腿、减少已成交的仓位，或保持敞口。
