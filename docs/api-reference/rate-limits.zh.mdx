---
title: API 速率限制
description: 为每个 API 接口规划请求突发和持续流量
---

限制在边缘强制执行。超过窗口配置容量的请求会被节流；交易写入必须满足其突发和持续限制。

## Gamma API

| 端点                 |               限制 |
| -------------------- | -----------------: |
| 所有 Gamma 路由      | 4,000 请求 / 10 秒 |
| `GET /events`        |   500 请求 / 10 秒 |
| `GET /markets`       |   300 请求 / 10 秒 |
| 组合事件和市场列表   |   900 请求 / 10 秒 |
| `GET /tags`          |   200 请求 / 10 秒 |
| `GET /public-search` |   350 请求 / 10 秒 |

## CLOB 读取

| 端点                         |               限制 |

| 所有 CLOB 路由               | 5,000 请求 / 10 秒 |
| `GET /`                      |    50 请求 / 10 秒 |
| `GET /book`                  |   200 请求 / 10 秒 |
| `POST /books`                |    80 请求 / 10 秒 |
| `GET /price`                 |   200 请求 / 10 秒 |
| `POST /prices`               |    80 请求 / 10 秒 |
| `GET /midpoint`              |   200 请求 / 10 秒 |
| `GET /prices-history`        |   100 请求 / 10 秒 |
| `POST /batch-prices-history` |    80 请求 / 10 秒 |
| `GET /data/trades`           |   150 请求 / 10 秒 |

## 交易写入

| 端点            |          突发 |             持续 |
| --------------- | ------------: | ---------------: |
| `POST /order`   | 2,400 / 10 秒 | 24,000 / 10 分钟 |
| `DELETE /order` | 2,400 / 10 秒 | 24,000 / 10 分钟 |

## 客户端指南

- 当需要多个订单簿或价格历史时优先使用批量端点。
- 缓存不随每次请求而变化的市场元数据。
- 对实时更新使用 WebSocket 流而不是轮询同一资源。
- 在重试中添加抖动，以便多个工作者不会同时重试。
- 限制每个 API 密钥和每个进程的并发。
- 为风险控制保留取消容量。

<Callout type="warning" title="将限制视为操作默认值">
  生产限制可以在不更改 API 版本的情况下更改。Gamma 值是兼容性目标；部署客户端 使用退避和可配置本地预算。
</Callout>
